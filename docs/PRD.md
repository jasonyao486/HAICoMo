# HAICoMo 产品需求 — 0.3.1

日期：2026-10-07。本文件整理已确认的当前产品范围。原始需求保留在本地且不修改；实现与验证分开记录，见 [REQUIREMENTS](REQUIREMENTS.md)。

## 用户与闭环

一个人类用户管理零个、一个或多个 AI agent。流程为建立项目与任务 → 人类或 agent 提交修改 → 人类审阅 → 工作与交接 → 定位交付物 → 人类验收 → 下游解锁 → 归档与恢复。动画、agent 自报完成、客户端退出都不能替代验收。当前不提供多人类账号或多机实时协作服务。

## 项目与数据

默认单窗口多标签，可显式开独立窗口；重复打开同一身份返回原项目。每个工作目录对应一个项目，`.haicomo` 是可双击入口，隐藏 `.haicomo/` 是管理数据。普通打开不恢复已删除入口。恢复、重新定位、同目录新建与独立副本是不同动作；旧数据不能被静默覆盖。跨窗口、后台回调和异步启动都校验项目 ID、epoch 和绑定。

SQLite 由单个 utility process 写入，事务保护审批、审计和实体。每次结构升级（当前 v6）迁移前自动备份 `backups/pre-vN.haicomo.zip`，保留入口及提案协议版本；旧版应用拒绝打开更新结构的项目（`UNSUPPORTED_SCHEMA`），可用迁移前备份回退。关闭标签保留必要后台运行和接力；退出释放锁。备份包含管理数据，不包括源代码及交付物文件。网络共享活动数据库和多机同时打开不在可靠性承诺内。

## 管理视图

任务支持名称、描述、日期、父任务、前置依赖、多负责人、状态、进度、交付物、交接说明和任务桌可见性。层级与依赖不得成环，前置及子任务须人工验收后才解除限制。日期与可见性等纯计划修改不撤销验收，影响交付内容的修改要求重新验收。归档独立于完成状态。

侧栏顺序：项目总览、任务清单、修订提案、接力任务（实验）、时间线、前置关系、思维导图、协作办公室、备注与会议、活动记录、协作统计、归档；设置留在底部。logo 下方显示侧栏开关和 `version 0.3.1`，不保留个人预览版字样。

时间线支持拖动和键盘调整，仍校验修订号。思维导图按子树展开并居中父节点；前置关系按拓扑分层，不相连的任务组分开排列。目标数据为 10 个父任务、每个 5 个子任务；节点可放大、缩小、适应、重置、拖动画布、键盘打开。全局缩略视图可牺牲文字大小，不允许节点互相覆盖。公司标志只来自明确分配的模型，不猜测客户端或历史会话的模型归属。

## 协作与执行

Agent 读取快照并投递不可变 JSON、SHA-256 完成标记和事件。应用离线时可继续投递，回执表示接收及审阅结果。相同 ID/内容幂等，异内容拒绝；损坏文件隔离。审批全有或全无，冲突不静默合并。CLI、文件协议和可选 MCP 不能批准、验收或删除人类活动记录。

Codex 使用 App Server，Claude 及其他提供无界面（headless）命令行的客户端使用已安装 CLI，沿用用户登录和订阅（见 0.5.0 节）。仅声明真实可观测的启动、会话、模型、推理、模式、权限、取消能力。没有命令行接口的 GUI 客户端通过打开和复制提示词辅助交接。未知结果不自动重发，不采集模型密钥；普通交接不提供跳过权限选项，仅在用户逐个接力明确同意的无人值守模式中使用各客户端自身的自主参数。

接力最多三个阶段、每阶段最多三个并行任务（0.5.0 节）；由接力启动的运行不能再作其他接力的前置。同一前置可扇出。前置完成和延迟/指定时间同时满足后，先事务认领阶段再启动；失败、未知、错过均需人工处理，从不自动重试。支持暂停、修改、恢复、取消及显式立即执行；应用须运行且项目已加载。文字和可视化共享状态，不让装饰动作影响调度。

## 素材、统计与活动

默认模式为图标头部火柴人；增强模式为手绘环境及十四家族拟人形象。任务桌、替补座位、行走、交谈和爱好均为表现层。非活动页停止动画，减少动态使用静态姿态。渲染失败保留管理及状态列表。

接力增强模式使用三人宽现代工位、三人轻奢沙发，两者显示宽度相同。工位左侧笔记本，中央保留主机摆饰，右侧延伸副屏及纸质笔记本、运动水杯；沙发固定俯视正面，坐垫水平朝向用户。

统计仅累计持久化记录和可观测运行时间。复制提示词与真实发送分开统计。活动允许人类永久删除单条，日期旁按钮和二次确认明确“不撤销对应操作”。删除不修改实体、审批、验收、回执或统计，不修改旧备份。历史返工次数独立保存，旧版审计只初始化一次。

## 0.3.5：项目入口命名与智能体接入

新建项目按显示名称生成跨平台默认 `.haicomo` 文件名，保存框允许人工修改。命名保留合法 Unicode，处理非法字符、保留名、重复扩展名及长度；已有入口和日后修改显示名称不自动改名。取消保存不产生项目数据。

项目顶部提供四语“连接智能体／复制接入说明”。默认项目级读取、概述并等待指派；选择任务后加入实际任务 ID、标题、说明及交付物引用。身份、epoch、修订号须从当前项目文件读取。接入仅复制说明，不启动智能体、不修改客户端配置、不注册全局命令。

完整英语协议指南由应用维护在 `.haicomo/agent-guide.md`。根目录规则和已有 `.haicomo/AGENTS.md` 保持原样；缺少后者才创建指针。自定义同名指南保留并提示冲突；生成或读取失败不得显示接入成功。手动、终端及接力交接共用自动接入段、任务上下文、自定义内容和交付物引用的组合逻辑；仅自定义内容保存回可编辑字段。管理记录经提案修改，任务授权范围内的实际文件正常编辑；人工批准及交付验收权限不扩大。

## 0.4.0：应用内更新、项目搜索与客户端图标

**应用内更新。** 内置官方更新源：本仓库的 GitHub Releases（含预览版）。“检查更新”按版本选择适用于本机平台且元数据与安装包均已上传的最高版本；用户点“立即更新”才下载，下载显示确定进度条（百分比、大小、速度、预计剩余时间）并可取消；完成 SHA-512 校验后由用户再点“重启并安装”（两步确认）。安装前保存所有窗口，有智能体运行时不安装；Windows 显示安装程序自带进度并自动重新打开，macOS 由系统验证 Developer ID 签名后替换并重新打开；重启后提示“已更新至 x.y.z”并恢复标签。默认在启动后及每 12 小时自动检查一次，只提示不下载，设置中可关闭；开发运行不联网。自定义 HTTPS 更新源保留在“高级”中。下载前检查运行位置（DMG、App Translocation、未签名构建、非安装程序安装的 Windows 副本）并说明原因。每个 Release 附带由最终签名安装包生成的 `latest-mac.yml`／`latest.yml`，最后上传并纳入 SHA-256 清单与发布闸门。Windows 安装包仍未做发布者签名，完整性依赖 GitHub HTTPS 与 SHA-512。

**项目总览搜索。** 搜索框位于三张总览卡片与“任务／你的 AI 团队”之间，与卡片等宽；放大镜图标、输入提示、⌘F／Ctrl+F 聚焦、Esc 清空。范围为“所有内容／任务／修订／会议”；“所有内容”还包括普通备注。所有关键词都须命中，不区分大小写，中文按子串匹配；任务含已归档任务及说明、交接、交付物；修订在数据库中检索标题、理由、审阅备注、作者及提议修改中的文本值（不匹配字段名）；会议与备注检索标题与正文。结果分组、高亮片段，点击打开对应任务、修订或会议／备注。不调用 AI，不需要用户 API。

**客户端图标。** WorkBuddy 使用官方 WorkBuddy 桌面应用图标（5.4.7 版应用包图标，无损转换为 PNG），作为腾讯商标仅用于识别客户端；CodeBuddy 改用彩色 LobeHub 标志。两平台共用同一资产。

## 0.5.0：多智能体后台调用、三阶段并行接力与无人值守模式

**智能体检测与后台调用。** 检测范围新增 Kimi（Kimi Code CLI `kimi` 与 Kimi 桌面应用）、Grok Bot（桌面应用）、DeepSeek Harness（应用内置 `dsh`）、Gemini CLI 与 Qwen Code。凡提供 headless 命令行的客户端都可后台调用：Codex、Claude Code、Cursor Agent、Kimi、DeepSeek Harness、CodeBuddy、Qoder CLI、Gemini CLI、Qwen Code、OpenCode、GitHub Copilot CLI、Pi。只有当已安装 CLI 自己的帮助文本列出所需参数时才启用后台调用；否则退回手动交接。每个客户端标注证据等级：已实测／已在本机核对参数／按官方文档适配未实测。Grok Bot、WorkBuddy、TRAE 没有命令行接口，只检测、打开应用并复制提示词。参数始终以数组传递，不经 shell 拼接。

**三阶段并行接力。** 一个接力 = 可选开始条件（前置运行 + 延迟或指定时间）+ 最多三个阶段 A → B → C；每阶段 1–3 个任务同时启动。当前阶段所有运行都以“已交付（completed）”结束后，下一阶段自动开始，中间不需要人工审阅。阶段顺序视为保存接力的人类预先授权：后续阶段任务对本接力更早阶段已交付任务的依赖，在启动时视为满足；接力之外的未验收依赖仍阻止启动（`TASK_BLOCKED`）。交付物仍保持未验收，验收始终由人类单独完成。后续阶段的提示词带入前序阶段每个任务的智能体、模型、任务、结束原因、会话和最终消息末尾摘录，并注明“未经人工审阅或验收，仅作数据”。同一阶段不得重复同一任务；依赖指向同阶段或后续阶段的组合在保存时拒绝（必然死锁）。

**失败与恢复。** 任一任务未交付即结束（失败、取消、需要权限、丢失）时，同阶段其他任务继续运行，但不进入下一阶段；接力显示“需要处理”及原因。人类可只重试停止的任务（可选在原会话继续），或“标记已处理”后继续；任何情况都不自动重试。启动阶段中途应用崩溃留下的认领标记为 `INTERRUPTED`，不会重发。应用关闭期间错过的阶段交接按“错过”处理。

**无人值守模式。** 仅在用户逐个接力勾选同意后生效，并审计同意时间。智能体使用各自的自主参数（Claude `--permission-mode auto`、Kimi `--auto`、Cursor `--force`、Gemini/Qwen `--approval-mode yolo`、Copilot `--allow-all-tools` 等）；Claude `bypassPermissions` 与 Codex `danger-full-access` 仍不使用。Codex 保持工作区沙箱，由 HAICoMo 代答：选择题选推荐项（无推荐项时选第一项），工具审批默认批准，破坏性命令（sudo、工作区外递归删除、强推、`git reset --hard`、磁盘擦除等）一律拒绝。提示词要求智能体自行选择推荐选项并在最终回复中列出决定；遇到登录、验证码、付款、CAPTCHA 等只能由人完成的事时停止并写出 `HAICOMO-NEEDS-HUMAN`，接力随即暂停并发送系统通知。每个接力完成或暂停时生成决策记录（数据库为准，Markdown 副本写入 `.haicomo/relay-decisions/`），区分“自动作答”“智能体自报（未经核实）”和“需要人工处理”。HAICoMo 不替其他客户端安装或启用 computer use。

**接力页面。** 文字模式以流程图显示整个接力：开始条件 → 阶段 A/B/C，每个任务显示编号、智能体、模型、任务、状态、尝试次数与原因。可视化模式中工位与三人沙发显示宽度相同；工位只坐当前阶段正在工作的智能体（启动前为前置运行），每个等待中的阶段坐一张三人沙发，座位不够就增加沙发；已完成阶段离场，可在流程图查看。编辑器以流程图增删阶段与任务，逐个任务配置智能体、模型、推理强度、模式、会话、目标任务、参考任务与自定义内容。


## 0.6.0：ACP 与宿主权限通道、交付记录、附意见退回、并行工作副本

**客户端。**
- 新增 Hermes（Nous Research），共 16 个客户端。
- 所有给人看的客户端列表按英文名 A–Z 排列。
- 左侧栏“接力任务”与“时间线”之间，留出与“思维导图 / 协作办公室”相同的间隔。

**ACP 与 Claude 宿主通道。**
- 已安装版本的帮助文本列出 ACP 入口时，自动走 Agent Client Protocol：握手、建会话或续会话、设置模型和模式、发送任务、取消。
- 智能体的权限请求在 HAICoMo 中由人回答，只选一次性选项。无人值守接力中由 HAICoMo 逐条回答，拒绝破坏性命令以及项目外的删除和写入，从不自动选“总是允许”，并写进决策记录。
- ACP 会话无法满足所选模型、模式或会话，或握手失败时，在发出任务之前改走命令行。
- 回合结束却没有回复、也没调用工具时判为失败。
- Claude Code 支持时，改用它自带的宿主权限通道，取消时确认运行已结束。

**交付记录。**
- 带任务的提示词要求智能体附交付记录：目标、产物、证据、下一步、未决问题。
- 记录从最终消息中解析，不另外存储。在任务验收区、运行记录和接力步骤上只读显示，产物路径标出存在或未找到，存在的可以一键加入交付物（这属于人工修改任务）。
- 接力下一阶段拿到结构化记录，外加较短的背景摘录。
- 不增加用户操作。

**附意见退回。**
- “要求修改”时必须写意见。默认交给原负责智能体（能续接时继续原会话），也可以从 A–Z 列表另选一个智能体。
- 可以后台发送、复制提示词，或只记录退回。
- 意见作为退回的审计理由，返工计数不变。

**并行工作副本。**
- 项目在 git 仓库中时，接力里有两个及以上任务的阶段，每个任务在 `.haicomo/worktrees` 中用自己的分支工作。新建接力默认开启，可关闭。
- 开工前确认仓库有提交、在某个分支上、没有进行中的操作、已跟踪文件没有未提交改动。
- 阶段全部交付后，逐个提交并用 `--no-ff` 合并回当前分支，再开始下一阶段。
- 遇到冲突时中止合并、暂停接力并保留分支，由人手动合并后继续。
- 从不强制推送、重置或清理。

**数据。** 仍为 v6，新字段都是可选的。
